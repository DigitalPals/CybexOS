# PXE boot investigation — 2026-10-23

Historical beta.1 record: both images below were superseded and removed at the
user's request. See the [beta.2 results](installer-graphics-beta2-2026-10-23.md)
for the current testing image, follow-up fixes and qualification limits.

The reported physical failure is a corrupted display after selecting NerdOS on
a Minisforum X1 Pro 370 (Ryzen AI 9 HX 370 / Radeon 890M). The photograph does
not provide a readable kernel error or establish which boot stage failed.

## Confirmed defects and changes

The original Beast image was
`nerdos-1.0.0-beta.1-20261023-ec5fa706073a.iso`. At inspection its SHA-256 matched
the previous handoff: `fe2b8739bd0b2ef030cd80d99716810f29fbec35e94a9969a78aee35bf305f1b`.
Its integrity and the running PXE service do not establish successful PXE boot.

- The generated GRUB and ISOLINUX menus use `/boot//nix/store/...` paths.
  iVentoy 1.0.41 logs `Failed to split path` and `not found in ISO file` for
  the initrd, and records `Initrd:0`. A direct optical-disk VM boot does not
  exercise this parser. The ISO module now canonicalizes these paths in the
  BIOS menu, external EFI menu and menu embedded in the EFI boot image.
- The ISO's early module set lacked the X1 Pro's Realtek RTL8125 Ethernet
  driver (`10ec:8125`, `r8169`). The initrd now carries common wired NICs and
  the packet-socket/NBD modules used for network-backed media. This preserves
  the ordinary ISO and the same fresh installer.
- At the user's request the ISO moves from Linux 6.18.57 to 7.2.11. The existing
  stable Nixpkgs pin (`da6dc0e7b26060f2f71ce3ef7088fb56ee44fa36`) provides 7.3
  as `linuxPackages_latest`, but its ZFS 2.4.4 packages support only through
  7.2. Evaluating the all-filesystems ISO with 7.3 fails on the broken ZFS
  kernel package. The image uses the pinned 7.2 series to preserve filesystem
  support; neither `allowBroken` nor a driver-disable workaround is used.
- `scripts/check-image-parity` now checks exact canonical kernel/initrd paths
  in both boot menus and requires the embedded EFI menu to match. Its developer
  shell includes `mtools` for reading the embedded menu.

These are confirmed packaging and PXE preparation defects. Their correction
alone does not prove that the physical display problem is fixed. Physical AMD
graphics, firmware/Secure Boot and end-to-end LAN PXE boot still need exercise.

The source snapshot was frozen before writing this evidence record. Existing
workspace changes are included in it; unrelated work was preserved. The original
testing image was preserved until the user requested cleanup during the beta.2
follow-up. No workstation deployment or release publication is part
of this task.

## Failed updater check and remaining qualification

The same-source `checks.x86_64-linux.vm` was actually exercised and **failed**
at the supervised package-staging request. Its isolated, offline guest tried to
fetch missing build dependencies, including Python 3.14.4, Bash and Binutils
sources, and failed with `Could not resolve hostname`. The updater reported
`Staging failed; working system retained`. The package and cleanup previews
did not complete, and no candidate was applied. This run does not establish a
successful staged update; the earlier image's successful updater evidence
cannot be attributed to this source snapshot.

Physical Minisforum boot/display recovery, end-to-end LAN PXE, installation,
installed trial boot/apply/confirmation/rollback and Secure Boot remain
unqualified. The corrected iVentoy scan and successful optical-disk VM boot
are separate observations, not a physical PXE success claim.

### Physical retest and follow-up diagnosis

The user booted the 7.2.11 image and confirmed **identical corruption**, after
the separate NerdOS GRUB menu and before any desktop. The 16:03:41 iVentoy log
confirms image 3 (the corrected image), not the older image, was selected.

A subsequent disposable UEFI/KVM PXE guest reached the real iVentoy service,
selected image 3 and booted Linux. Serial output then recorded a 90-second
timeout waiting for `/dev/disk/by-label/NERDOS_INSTALL`, followed by emergency
mode. This used isolated QEMU user networking with its own DHCP/TFTP and a
task-owned loopback HTTP relay; no LAN DHCP or PXE configuration was changed.
It reproduces a network-media failure, not the physical AMD screen corruption.

The installed iVentoy 1.0.41 payload's NixOS hook only inserts
`ventoy_disk.sh` before the words `mount the root` in `/init`. That script sets
up the NIC and NBD installation disk. The image uses systemd stage one, whose
`/init` is not that shell script; the hook installs no systemd unit. Finding the
initrd and carrying its NIC modules did not make this setup run. The live module
now selects NixOS's upstream scripted initrd, while installed machines retain
systemd stage one. Early native graphics and explicit diagnostic/text entries
are also being added; these changes require their own image and boot checks.

historical evidence record remains. Task-owned source snapshots, intermediate
